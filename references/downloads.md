# AGY staffer 内部下载指南

本文件只供执行下载的 AGY staffer 按需读取。调用方只交付链接、输出要求和有效授权；平台选路、具体命令、重试和验收由你完成，不要求调用方学习或代做。

仅处理用户给出的链接及范围。TK = TikTok；抖音和 TikTok 分别执行。链接清单每行一条，去重并保留来源；不从单条视频扩大成整账号下载。用户指定输出目录时用其绝对路径；否则沿用当前任务已有目的地，再无约定时使用当前任务目录下的 `downloads/`，创建目录并告知。不要仅因缺少非关键参数停下。

你已经是执行下载的 staffer；直接调用下载工具，不再递归启动 AGY。外层调用方负责后台任务的等待和结果收集。用户给出的链接、输出目录和有效授权持续复用；仅缺少关键授权或工具强制人工操作时暂停依赖步骤。AGY 的外层后台运行与 VidBee 内部等待是不同层次，VidBee 仍须 local/wait，不得使用 detach。

## 内部选路

- 抖音链接：使用下述 douyin-dl 路线，不使用 VidBee。
- TikTok / TK 链接：使用下述 VidBee 路线。
- YouTube 及其他 yt-dlp 支持的平台：使用下述 yt-dlp 路线。解析器存在不代表当前链接一定可下载。
- 用户明确指定工具时遵从该选择，仍保留授权和结果核验。工具缺失先检查 PATH 与已有安装，不自动安装或更改系统配置。

## 抖音：AGY → douyin-dl，不使用 VidBee

抖音下载工具不包含在本仓库中，需要使用者自行安装并授权。先定位当前环境中的 `douyin-dl` 及其完整 Skill 说明，并读取该说明。常见 Skill 位置为 `$HOME/.gemini/config/skills/douyin-downloader/SKILL.md`，但必须以实际安装为准。

以下示例假定 `douyin-dl` 已在 `PATH`。本地参数检查使用 `--help`，不触发下载。

在下面的已知前提满足后，单条命令形式为：

```sh
douyin-dl '用户原始抖音链接' -o '/绝对路径/输出目录' -n '唯一文件名' --json
```

批量时逐条调用；每条使用唯一文件名或子目录，避免标题重复覆盖。工具未提供 `--no-overwrites` 或链接清单参数；不要编造这些参数，已有文件先核验再跳过。

**原部署曾核验的工具行为（2026-09-09 源码检查，仅适用于该版本）：**

下面是适配时记录的兼容性与安全检查点，不代表所有 `douyin-dl` 实现都相同。使用者必须重新核对当前脚本；本仓库不附带脚本、Cookie 或历史工程。

- 脚本会自动读取其保存的抖音 Cookie，且可能回退到旧工程的 Cookie 文件。调用前确认已有授权覆盖该登录态及抖音下载用途；没有授权时，不因文件存在就调用此入口，先说明需使用哪一处登录态，不展示凭据。已有有效授权不重复询问。
- 现有脚本的 `get_ssl_ctx()` 关闭了 TLS 证书校验。在实际联网下载前，须先用任务内副本恢复正常证书校验，再按原参数调用该副本；不修改原全局脚本，不用关闭校验处理后续证书错误。副本中的 Cookie 来源须显式限定为已授权的原路径；复制脚本后 `__file__` 路径会变化，不能依赖原来的隐式定位或复制 Cookie。若没有本次授权需要的凭据，使用无凭据路径或询问缺失授权。
- 脚本可能同时保存说明文本和音乐；图片作品还可能用第一张图加音乐合成 MP4。用户要“下载原视频”时必须预检媒体类型，图片合成不能报作原视频；对图集保留来源并说明类型，不擅自做成视频。
- 不附加裁切、分离音轨、剪辑参数，除非用户要求。不要继承旧说明中“必为 4K／无损”的笼统承诺，以实际视频流为准。

这里记录使用前提；创建或阅读 AGY Skill 本身不运行下载、读取 Cookie 或修补全局工具。不要把“尚未验证”当作不可用；先检查现有入口和实际错误，并在授权范围内修正参数或使用安全的任务内副本。只有没有可行的已授权路径时，才交付清单及确切阻塞。抖音不自动退回 VidBee，也不擅自用第三方付费解析服务。

## TikTok / TK：AGY → VidBee

VidBee 不包含在本仓库中，需要使用者自行安装。读取当前已安装的 VidBee Skill；常见位置为 `$HOME/.gemini/config/plugins/vidbee/skills/vidbee/SKILL.md`，以实际路径为准。

以下示例假定 `vidbee` 已在 `PATH`。原部署使用固定 local / wait / no-retry 的包装器，曾核验 CLI `0.1.0`；该包装器不随本仓库提供。调用前须按当前 Skill 和帮助确认等效运行方式。

```sh
vidbee :version
vidbee -a '/绝对路径/links.txt' -P '/绝对路径/输出目录' --no-overwrites --download-archive '/绝对路径/已下载.txt'
```

- 一批链接用同一等待会话跑完；**不传 `--vidbee-detach`**。本机 local 模式队列不跨进程持久化，另开进程查 `:status` 不能找回旧队列。
- 不给下载命令加 `--print`；当前 CLI 会把它识别成 probe。`--dump-json` 只代表探测，不代表下载。不用 `--ignore-errors` 掩盖失败。
- 先用不读取 Cookie 的方式下载用户给出的公开视频。只有实际登录错误且已有相关浏览器登录态授权时才加 `--cookies-from-browser`。不读取整个账户库、不输出 Cookie，不处理 CAPTCHA。
- 单个返回的 `output.filePath` 可能只指最后一条，不能据此认为整批已成功。下载 archive 用于避免重复，不以 archive 单独证明媒体文件存在。

## 其他支持平台：AGY → yt-dlp

先用 `command -v yt-dlp`、`yt-dlp --version` 和必要的 `--help` 确认当前已有入口；合并音视频通常需要已有的 `ffmpeg`。yt-dlp 不包含在本仓库中；从 PATH 或用户指定入口寻找已有安装。不要因为探测成功就停止，下载阶段必须产生媒体文件。

单条公开视频的基本命令（目录须替换为本次实际目的地）：

```sh
yt-dlp --ignore-config --no-playlist --no-overwrites \
  --download-archive '/输出目录/downloaded.txt' \
  -f 'bv*+ba/b' -P '/输出目录' \
  -o '%(title).180B [%(id)s].%(ext)s' \
  --no-simulate --print 'after_move:filepath' \
  -- '用户原始链接'
```

- `--ignore-config` 避免继承无关下载配置和凭据来源。默认不读 Cookie；只有真实登录错误且已有对应授权时才使用明确指定的 Cookie 来源，不能扫描账户库或输出凭据。
- `--no-playlist` 避免单条链接意外扩展为播放列表；仅用户请求列表时改用相应范围。批量逐条记录结果，并保持唯一文件名及 archive，避免重复或覆盖。
- archive 命中或已有同名文件时，下载可能跳过且 `after_move:filepath` 没有输出；不能把空输出直接当失败或成功。根据视频 ID 和输出目录找到对应文件，核验后记为已存在；若 archive 记录存在但媒体缺失，在不覆盖现有文件的前提下对该项移除 archive 限制重新下载，不把旧记录当完成。
- `--print`、`--dump-json` 等可能启用模拟，下载命令显式加 `--no-simulate`；`--skip-download`、`--simulate` 和元数据输出不算下载完成。默认不写可能包含私人信息的完整 `.info.json`。
- 按用户要求选择质量；无要求时使用上述可用最高质量组合。缺少 ffmpeg 时可以下载可用的单文件音视频格式并说明限制，不自动安装依赖；不能把单独视频轨宣称为完整声画。
- 失败时保留具体错误。只在发现可修复原因时调整参数、格式选择或已授权配置再试；不要相同参数无限重试，也不使用忽略错误选项掩盖失败。登录、CAPTCHA、DRM、付费或服务限制需要真实前提，不能承诺绕过。已有可行路径时执行到实际文件，不仅返回建议命令。

## 验收和交付

核对每个输入对应的成功、跳过、失败或未完成状态；检查实际文件存在、非零大小，用本机 `ffprobe` 核验可读视频流与时长。检查有无音轨，但不要求原本无声的作品必须有音轨：按来源实际情况说明，图集按图集交付，不伪造声画。

向用户报告总数、成功/跳过/失败数量、输出目录和失败原因；必要时在输出目录保存简短下载清单。工具日志在当前项目 `work/` 保存且不得包含凭据。只继续失败或未完成项，不覆盖已核验成功的媒体。下载不包含自动剪辑、上传或发布。
