# 视频下载：平台分流

仅处理用户给出的链接及范围。TK = TikTok；抖音和 TikTok 分别执行。链接清单每行一条，去重并保留来源；不从单条视频扩大成整账号下载。用户指定输出目录时用其绝对路径。没有目录且上下文无法确定时，整理链接后询问目录。

下载使用 staffer 后台模式，先按 [CLI 调用方法](cli.md) 启动，再按 [jobs](jobs.md) 跟进结果。用户给出的链接、输出目录和有效授权持续复用；仅缺少关键授权或工具强制人工操作时暂停依赖步骤。AGY 的外层后台运行与 VidBee 内部等待是不同层次，VidBee 仍须 local/wait，不得使用 detach。

## 抖音：AGY → douyin-dl，不使用 VidBee

抖音下载工具不包含在本仓库中，需要使用者自行安装并授权。先定位当前环境中的 `douyin-dl` 及其完整 Skill 说明，告诉 AGY 读取该说明。常见 Skill 位置为 `$HOME/.gemini/config/skills/douyin-downloader/SKILL.md`，但必须以实际安装为准。

以下示例假定 `douyin-dl` 已在 `PATH`。本地参数检查使用 `--help`，不触发下载。

在下面的已知前提满足后，单条命令形式为：

```sh
douyin-dl '用户原始抖音链接' -o '/绝对路径/输出目录' -n '唯一文件名' --json
```

批量时逐条调用；每条使用唯一文件名或子目录，避免标题重复覆盖。工具未提供 `--no-overwrites` 或链接清单参数；不要编造这些参数，已有文件先核验再跳过。

**原部署曾核验的工具行为（2026-09-09 源码检查，仅适用于该版本）：**

下面是适配时记录的兼容性与安全检查点，不代表所有 `douyin-dl` 实现都相同。使用者必须重新核对当前脚本；本仓库不附带脚本、Cookie 或历史工程。

- 脚本会自动读取其保存的抖音 Cookie，且可能回退到旧工程的 Cookie 文件。调用前确认已有授权覆盖该登录态及抖音下载用途；没有授权时，不因文件存在就调用此入口，先说明需使用哪一处登录态，不展示凭据。已有有效授权不重复询问。
- 现有脚本的 `get_ssl_ctx()` 关闭了 TLS 证书校验。在实际联网下载前，须先用任务内副本恢复正常证书校验，再按原参数调用该副本；不修改原全局脚本，不用关闭校验处理后续证书错误。副本中的 Cookie 来源须显式限定为已授权的原路径；复制脚本后 `__file__` 路径会变化，不能依赖原来的隐式定位或复制 Cookie。若没有本次授权需要的凭据，使用无凭据路径或询问缺失授权。
- 脚本可能同时保存说明文本和音乐；图片作品还可能用第一张图加音乐合成 MP4。用户要“下载原视频”时必须预检媒体类型，图片合成不能报作原视频；对图集保留来源并说明类型，不擅自做成视频。
- 不附加裁切、分离音轨、剪辑参数，除非用户要求。不要继承旧说明中“必为 4K／无损”的笼统承诺，以实际视频流为准。

这里记录使用前提；创建或阅读 AGY Skill 本身不运行下载、读取 Cookie 或修补全局工具。没有当前已验证的可用路径时，交付已整理清单及确切阻塞，抖音不自动退回 VidBee，也不擅自用第三方付费解析服务。

## TikTok / TK：AGY → VidBee

VidBee 不包含在本仓库中，需要使用者自行安装。告诉 AGY 读取当前已安装的 VidBee Skill；常见位置为 `$HOME/.gemini/config/plugins/vidbee/skills/vidbee/SKILL.md`，以实际路径为准。

以下示例假定 `vidbee` 已在 `PATH`。原部署使用固定 local / wait / no-retry 的包装器，曾核验 CLI `0.1.0`；该包装器不随本仓库提供。调用前须按当前 Skill 和帮助确认等效运行方式。

```sh
vidbee :version
vidbee -a '/绝对路径/links.txt' -P '/绝对路径/输出目录' --no-overwrites --download-archive '/绝对路径/已下载.txt'
```

- 一批链接用同一等待会话跑完；**不传 `--vidbee-detach`**。本机 local 模式队列不跨进程持久化，另开进程查 `:status` 不能找回旧队列。
- 不给下载命令加 `--print`；当前 CLI 会把它识别成 probe。`--dump-json` 只代表探测，不代表下载。不用 `--ignore-errors` 掩盖失败。
- 先用不读取 Cookie 的方式下载用户给出的公开视频。只有实际登录错误且已有相关浏览器登录态授权时才加 `--cookies-from-browser`。不读取整个账户库、不输出 Cookie，不处理 CAPTCHA。
- 单个返回的 `output.filePath` 可能只指最后一条，不能据此认为整批已成功。下载 archive 用于避免重复，不以 archive 单独证明媒体文件存在。

## 验收和交付

核对每个输入对应的成功、跳过、失败或未完成状态；检查实际文件存在、非零大小，用本机 `ffprobe` 核验可读视频流与时长。图集或不含音轨的原始作品按实际类型说明，不伪造声画。

向用户报告总数、成功/跳过/失败数量、输出目录和失败原因；必要时在输出目录保存简短下载清单。工具日志在当前项目 `work/` 保存且不得包含凭据。只继续失败或未完成项，不覆盖已核验成功的媒体。下载不包含自动剪辑、上传或发布。
