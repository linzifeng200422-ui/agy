# 后台任务管理

以下命令均通过 `node "${CODEX_HOME:-$HOME/.codex}/skills/agy/companion/agy-companion.mjs"` 执行；工作目录与启动一致。

1. 保存启动返回的 job ID、工作目录、模式和模型。
2. 对该 ID 执行 `wait <id> --timeout 50s`，保留宿主 exec 会话并收集结果。每个任务仅一个在途 wait；多个独立任务可并行等待。宿主等待单次不超过 60 秒，以便响应用户。
3. 退出 2 是等待软到期，原任务仍运行，继续等待同一 ID。不能重发任务。
4. 收到结果后核验真实成果，必要时检查文件与 diff。exit 0/done 只证明调用交付了响应。

| 命令 | 用途 |
| --- | --- |
| `observe <id>` | 用户询问进度，或失败/需要干预时读取有限快照 |
| `status <id>` | 查询任务状态与诊断 |
| `result <id>` | 读取已保存的完整结果 |
| `cancel <id>` | 请求停止并核实取消完成；不会撤销已有改动 |
| `continue --job <id> --prompt-file <文件>` | 在已结束任务的会话上追加工作，创建关联的新任务 |
| `restart <id>` | 使用原任务说明和配置新开会话，仅在有证据需要重新执行时使用 |

不要以例行状态汇报为由反复 observe/status、读取日志或中间产物。可以报告已知阶段、推进其他独立工作；收集正在等待的命令输出是正常结果收集。后台任务不能自动安排未来 Codex 唤醒。

## 状态与恢复

- **0**：已有响应；检查正文、警告及成果，不能直接宣布用户目标完成。
- **1**：参数或命令错误；按报错修正。
- **2**：任务仍在运行；继续 wait，不重启。
- **3**：错误/崩溃；看实际原因。疑似假崩溃时核对启动和收集的权限上下文及工作区。
- **4**：已取消；检查部分产物并报告。
- **5**：超时且有可续接会话；核对原始诊断和部分改动后决定恢复。

硬时限停止执行与 wait 软到期不同。恢复前核对已有成果，避免重复下载、上传、付费或写入。同一授权范围的恢复不自动增加聊天确认：存在可行恢复路径且不会重复外部影响时，优先 continue 指向原任务，按实际需要扩大时限（最多 120m）或缩小任务；无新证据不机械反复重试。费用、授权或目标发生变化，才询问缺失部分。

运行中的任务不接受 follow-up，也不会排队。反馈可等时收完再 continue；必须立即改方向时 cancel、确认终止并核对部分产物，再按已授权的新方向 continue。

认证、配额、服务地区或明确权限拒绝不自动重试，也不自动切换模型/出口。失败日志与元数据保留，正常结果清理部分临时流文件；正文与诊断分别解读。网络偶发错误查明后最多一次定向重试。

禁止无目标使用“latest”续接无关任务；优先显式 job ID。迁移前直接 CLI 会话不在这里的注册表中，不伪造关联。
