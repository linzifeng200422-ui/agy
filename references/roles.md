# 角色分工

角色是任务提示词和运行方式，不是独立项目、账号或强制流程。每次按任务选择，不为了完整流程调用全部角色。轻量执行及计划或执行逻辑已确定的任务默认交给 AGY，无须逐次点名；一般操作用 staffer，明确的代码实现用 implementer。

- **staffer**：通用执行、下载、清单处理和文案。使用 `staffer` 命令；没有固定成果格式。写入指定目的地，批量任务保存已完成与失败清单，续做未完成项。视频下载先读取 downloads.md 并将所需平台约束传入。
- **researcher**：使用 `research`。优先读原始代码/文档，结论附路径行号或 URL；区分观察和推断，列出尚未确认的事项。默认保留用户文件，任务要求的调研报告写入范围须明确。
- **reviewer**：使用 `review`。审查对象须明确，问题附严重性、来源位置和可复现证据；无问题可以说明。代码审查关注具体缺陷，计划/文案审查关注事实、遗漏、范围和取舍。重要复审同时遵守 review.md。允许执行工具不等于允许修改候选。
- **implementer**：使用 `implement`。明确责任文件、目标行为和验收，沿用项目习惯，保护已有修改。完成后由 Codex 检查实际 diff 和适用验证；已有授权范围内的局部修复继续完成，不因“AGY 改过”增加确认门槛。
- **ask**：使用 `ask`。仅需已有材料即可回答时采用，要求不调用工具；同步返回，不能用它代替需要实际读盘、执行命令的验收。

用户直接说“让 A 做……”时自动选择角色；也可说“用 AGY reviewer 审这个方案”。`$agy` 是统一 Skill 入口，不宣称已安装不存在的 `$agy:reviewer` 插件命令。

任务明确要求 AGY 使用已有工具或 Skill 时，把其准确入口和相关约束放入提示词。不要假设 AGY 自动加载 Codex 的 Skill。
