# AGY 只读复审约定

Codex 负责候选稿、证据核验和最终判断。实质性计划、架构/技术决策、调研/诊断/审计结论、重要交付及相关验收判断，交付前做一次 AGY 只读复审。纯交谈、澄清、进度、简单事实、翻译、机械格式处理与低影响局部修改不触发；用户明确免除时跳过。

执行任务只复审最终成果，不逐个复审内部计划或进度；若用户只要计划，审该计划。风险动作所需的复审在动作前完成。

## 复审输入

- 固定同一目标、范围、最少证据、验收标准和候选版本（绝对文件路径及 commit 或 SHA-256）。
- 写明“只读审查、禁止修改任何文件”，禁止子代理、后台任务和再次调用 AGY。不给凭据、令牌或无关私人材料；必要私人内容没有相应用途授权时先脱敏。
- 要求输出具体问题、严重性、文件/来源位置、可复现证据及建议；无问题可以直接说明，不为了复审而找问题。
- 需要 AGY 独立读盘/执行验证时使用 reviewer（`review` 命令），读取 [cli.md](cli.md) 与 [jobs.md](jobs.md)，默认 unrestricted；提示词明确禁止修改候选文件。复审前后 Codex 对候选文件做 SHA-256 核对，不以 git status 没变化证明内容没变。
- 仅需所附材料时可用 ask，要求不读盘、不执行工具。说明此审查覆盖的是所附材料；不能代替用户要求的实际读盘或命令验证。
- 默认模型固定 Gemini 3.8 Flash high。若 AGY 正参与实现，等候选收敛后另开 reviewer 会话，不复用执行会话冒充独立复审。


## 裁决与次数

按原始证据逐条裁决，不按模型票数。采纳实质性修正后最多追加一次定向复审。仍有可复现且未解决的 P0/P1 时标记未就绪，不无限循环。

AGY 起草、执行或自行声称完成不等于独立复审。若 AGY 参与候选稿制作，使用新会话检查 Codex 整理后的最终版本；同一轮已有有效复审则不重复调用。

## 不可用与状态

AGY 不可用时，普通任务完成 Codex 自检后可交付并标 `AGY_REVIEW: UNAVAILABLE`，附已核实原因；不声称多模型通过。`command` 在非交互模式被拒绝时，先核对是否遗漏已授权的调用参数、命中现有权限规则或确实缺少新授权，不能一律要求用户再次确认。宿主或明确权限拒绝不自动重试；不能把退出 0 当作复审通过。高风险待执行动作或用户明确要求双路通过时，保持该动作待审，`AGY_REVIEW: PENDING` 并注明原因，其他已授权工作继续。

修改调用规则后的验证必须包含所修复的实际路径：纯文本返回成功只证明纯文本调用可用；修复读盘／命令任务时，实际核验相应工具成功、结果正确和文件状态，不能用零工具调用的 PASS 代替。

迁移前的可选备用路径继续保留：AGY 不可用时，如果当前环境允许且已有相应委派授权，可用独立 Codex 子代理补充复核；这不替代用户明确要求的 AGY 复审，状态仍为 `AGY_REVIEW: UNAVAILABLE`，不增加普通任务的交付门槛。

最终仅对适用任务给一句：

- `AGY_REVIEW: PASS`：首轮无 P0/P1，且无需实质修正。
- `AGY_REVIEW: REVISED`：已采纳修正且无剩余 P0/P1。
- `AGY_REVIEW: PENDING`：仍有阻塞或必要复审未完成。
- `AGY_REVIEW: UNAVAILABLE`：实际复审调用未获得有效结果。
- `AGY_REVIEW: SKIPPED`：适用任务被用户明确免除。

简单不触发的任务无需附复审状态。不可用不冒充 PASS，Codex 自检与 AGY 复审分别说明。
